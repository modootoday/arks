# Core build slice

## Goal

Deliver an ordered, **bottom-up** implementation plan for arks **inner/core** modules so an AI can implement smallest crates first with no design gaps in the core ownership zone. Normative principles: [[sot:root/product-intent]], graph: [[sot:root/crate-architecture]], model: [[sot:root/core-object-model]]. Authoritative verification venue for interop claims: [[sot:root/product-verification-clean-room]]. Git semantics: [[sot:root/git-compat-surface]].

Whole-product phase letters (**C→S→R→P→L→H→Pa→Pb→Pc→E**) are owned by [[plan:root/20261108082148]]; program milestones (**M0–M10**) and **CLI-parity production = M9** by [[sot:root/program-roadmap]]; this plan details **core crate packaging** aligned to that ladder. Crate import edges remain [[sot:root/crate-architecture]]. If a core slice packaging row and a phase/milestone exit disagree, **phase/milestone exits** win for product claims; rings win for dependency direction.

**Aligned order (normative):** hash/OID → loose objects (**M1**) → store facade (**M2**) → refs + index + repo (**M3**) → pack + protocol (**M4**) → CLI foundation (**M5**) → remote (**M6**) → porcelain waves (**M7–M9**, production at M9) → lease (**M10**). CELIR blocked side track.

Non-goals for this plan: inventing CELIR APIs; implementing L2+ leases before L0; rewriting git-compat/remote/clean-room SoTs; Wave-1 Cargo work until operators confirm ([[plan:root/20261108085816]]).

## Steps

### Slice order (smallest first)

Execute in order. Do not start slice *N+1* **product claims** until slice *N* acceptance is met for the claimed subset. Host unit tests may lead; **verified** requires clean-room when the gate exists.

### First engine track (M1 → early M3)

1. **Hash + OID** — `arks-hash`, `arks-oid`
2. **Loose objects** — `arks-object`
3. **Store facade + filesystem backend** — `arks-store` (CELIR slot empty)
4. **Refs + index + repo** — `arks-refs`, `arks-index`, `arks-repo`

Each PR must label clean-room vs host-advisory; product “verified” only via [[sot:root/product-verification-clean-room]].

### Workspace bootstrap (once; Wave-1)

1. Root virtual Cargo workspace and `crates/` members matching [[sot:root/crate-architecture]] — **only after** Wave-1 confirmation.
2. Update crate-architecture `rel.governs` when paths exist (L5).
3. Pin clean-room image/Git when Docker recipes land (open decisions — do not invent digests here).
