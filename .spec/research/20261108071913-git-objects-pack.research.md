# Git objects and pack formats

## Question

What on-disk and over-the-wire object encodings does stock Git document as interchangeable?

## Method

Primary reads of gitformat-loose, gitformat-pack, gitformat-chunk, gitformat-commit-graph, gitformat-bundle, gitformat-signature, plus layout notes in gitrepository-layout. Summarize only; link for normative detail.

## Findings

### Loose objects — gitformat-loose

- **URL:** https://git-scm.com/docs/gitformat-loose
- **Store path:** `$GIT_DIR/objects/[0-9a-f][0-9a-f]/*`
- **Content:** zlib-compressed stream of `type SP size NUL` + payload; object id is hash of **uncompressed** bytes (SHA-1 or SHA-256 per repository object format).
- **Types:** `blob`, `tree`, `commit`, `tag`.
- **Compat map:** with `compatObjectFormat`, mappings under `$GIT_DIR/objects/object-map/map-*.map` (see same page).
- **Compat impact:** GIR must produce bitwise-valid loose objects stock Git can `cat-file`; unknown types must not be invented.

### Packfiles and indexes — gitformat-pack

- **URL:** https://git-scm.com/docs/gitformat-pack
- **Paths:** `pack-*.pack`, `pack-*.idx`, optional `pack-*.rev`, `pack-*.mtimes`, `multi-pack-index`
- **Pack header:** signature `PACK`, version **2 or 3** (Git generates v2), object count; trailer is pack checksum.
- **Object encoding:** type+length varint; undeltified zlib data, or `OBJ_REF_DELTA` / `OBJ_OFS_DELTA` with compressed delta.
- **Idx v1:** 256×4 fanout + sorted (offset, name) entries + trailers.
- **Idx v2:** magic/version, fanout, names, CRCs, 4-byte offsets, optional 8-byte large offsets, trailers — needed for large packs.
- **Reverse index `.rev`:** maps pack position → idx position; optional acceleration.
- **MIDX:** chunk-based multi-pack index (chunk rules in gitformat-chunk); bitmaps may accompany packs (bitmap-format technical doc).
- **Compat impact:** readers must accept documented pack/idx versions; writers should prefer formats stock Git still generates unless capability/config selects newer.

### Chunk container — gitformat-chunk

- **URL:** https://git-scm.com/docs/gitformat-chunk
- Shared TOC: `(C+1)` rows of `{4-byte id, 8-byte offset}`, terminating zero id; used by commit-graph and MIDX.
- Unknown optional chunks: follow each format’s ignore/require rules; do not invent chunk IDs.

### Commit-graph — gitformat-commit-graph

- **URL:** https://git-scm.com/docs/gitformat-commit-graph
- **Paths:** `objects/info/commit-graph` or `objects/info/commit-graphs/*`
- Header `CGPH`, version 1, hash version (1=SHA-1, 2=SHA-256); mismatch → ignore with warning (per doc).
- Chunks include OID fanout/lookup, commit data, optional generation data / Bloom / extra edges / base graphs.
- **Compat impact:** pure cache; wrong graph must never change object identity. Prefer omit over write-incompatible graph.

### Bundles — gitformat-bundle

- **URL:** https://git-scm.com/docs/gitformat-bundle
- v2: `# v2 git bundle` + prerequisites + refs + pack.
- v3: adds `@capability` lines; unknown capabilities abort (no negotiation).
- Documented capabilities include `object-format`, `filter` (promisor pack after unbundle).
- **Compat impact:** GIR bundle I/O must match ABNF on that page.

### Signatures — gitformat-signature

- **URL:** https://git-scm.com/docs/gitformat-signature
- Detached signatures embedded in tags/commits/pushes; armor headers for `gpg` / `ssh` / `x509` per `gpg.format`.
- **Compat impact:** do not re-canonicalize signed payloads; preserve signature blocks stock Git verifies.

### Object content shapes (command docs + user manual)

Object **payload** layouts (tree entries, commit headers, tag headers) are specified across plumbing docs and the User Manual rather than a single `gitformat-object` page. GIR must treat stock Git’s accepted encodings as normative and cite plumbing/`git` glossary when implementing parsers. Primary hubs:

- https://git-scm.com/docs/user-manual
- https://git-scm.com/docs/gitglossary
- https://git-scm.com/docs/gitrepository-layout
