# Git refs and reftable

## Question

What ref storage, naming, packing, and reflog behaviors are publicly documented for interop?

## Method

Primary: gitrepository-layout, gitprotocol-common (refname ABNF/rules), reftable technical doc, git-pack-refs / git-check-ref-format / git-update-ref man pages, repository-version for `extensions.refStorage`.

## Findings

### Loose refs and HEAD — gitrepository-layout

- **URL:** https://git-scm.com/docs/gitrepository-layout
- Refs live under `$GIT_DIR/refs/` (`heads`, `tags`, `remotes`, `replace`, …).
- `HEAD` is a symref (or detached object name); bare repos still require `HEAD`.
- `packed-refs` stores the same information more densely; see `git-pack-refs`.
- `logs/` holds reflogs (`logs/HEAD`, `logs/refs/...`) as documented via update-ref / layout.
- `refs/replace/` is the exchangeable replace mechanism (preferred over legacy `info/grafts`).
- Worktree / `commondir` / `$GIT_COMMON_DIR` rules split which ref paths are shared vs per-worktree.

### Ref naming — gitprotocol-common + git-check-ref-format

- **URL:** https://git-scm.com/docs/gitprotocol-common
- Refnames are hierarchical octet strings; rules include: no component starting with `.`, must contain `/` (except special `HEAD`), no `..`, no control chars / space / `~^:?*[` , no trailing `/` or `.`, no `.lock` suffix, no `@{`, no `\`.
- Command contract: https://git-scm.com/docs/git-check-ref-format
- **Compat impact:** GIR must reject the same illegal names stock Git rejects when speaking the protocol or writing refs.

### Packed-refs

- Documented in layout + https://git-scm.com/docs/git-pack-refs
- Text file of object-id / refname lines; peel lines with `^{}` as used in advertisements.
- Concurrent updates use documented locking via `git-update-ref` patterns (see that man page).

### Reflog

- Layout places reflogs under `logs/`.
- Format/behavior primarily through https://git-scm.com/docs/git-reflog and https://git-scm.com/docs/git-update-ref
- Not a separate `gitformat-reflog` man page at research time; treat command docs + layout as primary, and avoid inventing fields.

### Notes

- Notes store under `refs/notes/*` per https://git-scm.com/docs/git-notes
- Interop: notes refs may be transferred like other refs when refspecs include them; object payloads are regular commits/blobs as implemented by notes.

### Reftable — technical doc

- **URL:** https://git-scm.com/docs/reftable
- Binary table format for refs and reflogs; stack of tables under a reftable directory.
- Selected via repository extension `extensions.refStorage=reftable` (see git-config / repository-version).
- **Compat impact:** if GIR writes reftable, it must match this format and set repository format version / extensions so unaware Git refuses rather than corrupt. Reading both files backend and reftable is required for broad interop.

### Symrefs and special refs

- Layout + glossary describe symrefs (`ref: refs/heads/...`).
- Protocol advertisements may include peeled tags `ref^{}` (gitprotocol-pack / v2 ls-refs).
